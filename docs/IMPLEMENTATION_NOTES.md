# 本轮实现与关键调整

## 设计来源

用户确认的最后一张多方案图：专业效率版作为工作台主体，简洁创作版作为首页，角色对话与音色库作为同一应用的工作区；不把多个方案做成互不相通的软件。

保留深色窄侧栏、浅色主工作区、蓝色主操作、卡片音色与底部波形。人像不作为虚构“已训练音色”的证明；使用清晰的声纹图标和参考/占位状态。

## 新 API（沿用认证）

- `GET /api/v3/studio/status`：服务、执行器、模型文件存在性、依赖位置和测试模式。明确 `hash_verified=false`，没有凭一个文件宣称就绪。
- `GET /api/v3/workspace`：返回 `revision` 和 `data`；首次为空。
- `PUT /api/v3/workspace`：`expected_revision + data`；冲突 HTTP 409；相同快照的丢响应重发安全。
- `POST /api/v3/segments/submit`：`request_id, project_name, items[]`；各项包含 `client_segment_id,text,voice_ids` 和原 JobRequest 参数。HTTP 202；相同编号同内容只返回原回执，不增加任务；相同编号不同内容 HTTP 409。
- `POST /api/v3/voices/match`：参考文件 SHA-256 查重；不会静默更改已有转写或授权。
- `POST /api/v3/exports`：当前选择任务 ID＋对应文稿＋句后停顿；格式 ZIP/WAV/MP3。音频不存在、未完成或文稿已变化时拒绝错误交付。

任务、音色读写、排队暂停、取消、音频读取继续调用已检查的 `/api/v1` 路由。对 v3 产生的任务，旧 retry 接口会拒绝原位覆盖。

## 扩展边界

当前逐句页面不是复杂 DAW；没有音频块拖动裁剪、多轨混音、ASR、配额计费、联网文案模型或全自动导演代理。UI 中不显示“已完成”来替代这些尚未开发的功能。

前端“锁定”保护文字、音色、批量参数和生成，并不禁止改变句子顺序。删除有历史的句子会额外确认；服务端音频仍保留。已生成 Take 的文字与音色 ID 是快照，文稿变更会标脏；尚未提供声音参考文件的版本替换界面。

原模型及来源引用：`Soul-AILab/SoulX-Podcast-1.7B-dialect`；固定 revision 由原归档 manifest 给出。本工程未声称训练了新模型。
