# SoulX Studio 3.0.1-preview.1 · 双平台安装说明

**这是原生在线安装入口的内测版，不是完整离线包，也不是已通过 Mac / Windows 实机与真实粤语验收的正式版。**

## 下载哪个版本

| 文件 | 目标电脑 | 能力范围 |
|---|---|---|
| mac-arm64 | Apple Silicon Mac，目标 macOS 13+ | 工作台；可选择安装本机语音组件 |
| windows-x64 | Intel / AMD x64，目标 Windows 10/11 | 工作台；可选 CPU 或 NVIDIA CUDA 12.6 语音组件 |
| mac-intel | Intel Mac，目标 macOS 13+ | 本版仅工作台；暂不开放本机语音依赖安装 |

版本对应处理器架构，不是按显卡区分。没有发布 Windows ARM / 32 位、Linux 用户版或签名 DMG/MSI。

## Mac 使用

解压 ZIP，将 `SoulX Studio.app` 放到“应用程序”中，然后双击。
应用会打开本机的“安装与运行中心”。无需预装 Python、Node、Go 或打开终端。
选择“先安装工作台”或“安装本机配音组件”，确认允许下载官方组件后点击“安装并启动”。

本包未完成 Developer ID 签名和 Apple 公证；操作系统可能拒绝打开。不要关闭 Gatekeeper 或执行绕过系统安全校验的命令。遇到系统阻止说明这份预览包尚不满足该电脑的分发信任要求，并非已经一键安装成功。

## Windows 使用

解压 ZIP，双击 `SoulX-Studio-Setup.exe`，浏览器会打开本机安装中心。
它是原生 x64 程序，不依赖用户预装 Python。按上述步骤选择用途安装。
成功后尝试创建开始菜单的“​SoulX Studio”快捷方式（无须管理员权限）。

本版尚未完成 Windows 发布者签名与 SmartScreen 信任验收。若系统或组织策略阻止运行，不应修改安全策略绕过；保留错误信息用于后续签名分发处理。没有注册为 MSI / 系统“应用与功能”卸载项。

## 两种用途务必分清

**先安装工作台**：自动准备独立 Python 3.11、API、前端和音频文件处理环境。可编辑、管理项目和参考声音；没有模型和语音依赖时不能生成配音。

**安装本机配音组件**：在上述基础上安装匹配的 Torch / torchaudio 和语音依赖，校验主模型及辅助 tokenizer。主模型约 5.45 GB，额外依赖及辅助资源另计。可填写已有模型目录，校验合格的文件不重复下载。`允许下载缺失的模型与辅助语音资源` 同时控制补齐辅助 tokenizer；仅有主模型不等于离线资源完整。

Windows CPU 路线不要求 NVIDIA 显卡，但真实速度与内存尚未实测。CUDA 路线只安装软件依赖，不安装显卡驱动；CUDA 不可用时会报错，而不是宣称硬件就绪。Intel Mac 本版只支持安装工作台。

建议先安装工作台确认可以打开，再从运行中心停止服务并补装语音组件。第一次配音使用一条约 50 字的粤语文稿和获授权的参考声音进行试听；然后测试多条文稿。没有通过这些步骤之前不能宣称稳定批量配音已验收。

## 网络与下载

首次安装是在线安装，需要官方软件源可访问。默认没有内嵌 Python、数 GB 权重和依赖 wheel；本包内嵌的是前端、后端代码与安装程序。

下载固定 uv 0.10.0 官方归档，验证其官方 SHA-256 后使用；uv 下载托管 Python 并在独立目录安装依赖。软件源包括 GitHub / Astral、PyPI、PyTorch、Hugging Face 和 ModelScope。没有执行下载来的 shell 脚本，没有要求用户提供账户密钥。

网络、空间、文件校验或包兼容出现问题时，安装中心显示失败与日志，不显示假成功，不替换旧版本。主模型下载支持续传与校验；运行工具和依赖的恢复行为由各自下载缓存处理。直接依赖固定版本，但本轮尚未生成三个目标平台完整的传递依赖锁文件，因此首次完整解算仍是待验收项。

## 数据保存位置

- Mac：`~/Library/Application Support/SoulXStudio/`
- Windows：`%LOCALAPPDATA%\SoulXStudio\`

`releases/` 是代码；`runtime/` 和 `environments/` 是运行时；`models/` 是默认模型目录；`cache/` 是下载与辅助资源；`workspace/` 是项目数据库、声音和结果；`logs/` 是诊断日志。外部指定的模型目录不搬移、不删除。

旧工程数据不会自动导入或覆盖。迁移前在旧工作台导出备份；新版第一次是独立工作区。若选择复制服务工作区目录，须先停止两端服务并备份，不能复制正在写入的 SQLite 目录。JSON 备份不等于包含所有仅存于旧服务器路径的音频，详见旧版说明。

浏览器保存和 SQLite 服务保存仍是两条明确的存储路径：在工作台“设置与模型”切换到本机工作区，确认“已保存到本机工作区”；不要把临时浏览器预览当成持久备份。

## 打开、停止和恢复

首次服务默认在本机 `127.0.0.1:18781/app/`；运行中心默认 `127.0.0.1:18779`。只绑定回环地址，不是公网网站。

以后打开同一应用会识别已安装环境并启动工作台。关闭浏览器不等于停止服务。需从安装中心点击“停止服务”，再点“退出运行中心”。运行中的语音任务阻止退出；排队任务保留。为避免关机过程中又领取新任务，安全退出会暂停队列；再次使用时需要到“任务”中恢复队列。

端口已被占用时不杀掉其他程序、不误认其他服务已启动；显示具体错误。每次启动均用本次随机身份校验真正的服务进程。

## 更新与移除

更新前建议导出重要项目。新安装使用单独的环境和代码目录，不把新文件覆盖到旧环境；服务启动检查失败会恢复旧安装记录。新代码并未提供自动删除旧环境的按钮，避免误清理资产。

停止服务并退出运行中心后，移除 `.app` / `.exe` 或快捷方式只是移除入口，用户目录数据保留。需要回收空间时先备份 `workspace/`、模型和参考声音，再自行决定清理范围。当前版本不提供自动卸载器。

## 开发与验证

开发者可运行：

```text
python scripts/build_desktop_installers.py
```

构建需要 Go 1.23+ 与 Python 3.11+；这是开发者要求，不是终端用户要求。构建使用标准库，不联网拉 Go 依赖；生成原生 PE / Mach-O 与 Mac app ZIP。每个 ZIP 的系统实测、签名和公证状态必须另外验收。

本轮完成的 Linux 测试与交叉编译见 `CROSS_PLATFORM_TEST_REPORT.md`。`.github/workflows/desktop-checks.yml` 是目标系统测试模板，本轮未提交或运行云端 CI，不能把工作流文件当成平台测试通过。
